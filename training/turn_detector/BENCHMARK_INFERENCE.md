# Frozen benchmark inference

Colab validation: seven synthetic freeze/recovery contracts passed; all five saved pilot head artifacts loaded and predicted causally on synthetic features; Arrow/soundfile decoded synthetic16kHz/24kHz audio successfully. Full benchmark/NeMo inference and GPU recovery reproducibility remain unverified. No benchmark data was opened by these checks. Evidence: benchmark-runtime-smoke.json.

`benchmark_infer.py` accepts existing plain/auxiliary MLP, causal GRU, and the two predeclared equal ensemble bundles. It runs on a prepared Colab runtime only. No training, scorer or annotation loader is invoked. The upstream dataset resolver reads annotations, so this implementation follows its Arrow/parquet approach but projects only conversation IDs and the two audio columns. Published dev and test revisions are hardcoded; the golden test repository is never accessed.

Required `--feature-manifest` is metadata from the exact cache used to train the head. Its checksum must match each head's recorded training manifest. Each row's encoder checksum must match the selected encoder (absent for frozen base). No feature arrays or annotation sidecars are opened. Continued encoders additionally require the original `encoder-identity.json` and `causality.json`; checkpoint source, train-only audit, revision, update, recipe, manifest/split identity and all three synthetic causality checks must agree.

Example remote dev run (replace paths with approved artifacts):

```sh
python benchmark_infer.py --split dev --checkpoint /content/model/best.pt \
  --feature-manifest /content/cache/manifest.json --out /content/benchmark-dev \
  --gate mean --batch-size 4 --dev-cache
```

For a continued encoder, append all three:

```sh
--encoder-checkpoint /content/continuation/latest.pt \
--encoder-identity /content/continued-cache/encoder-identity.json \
--encoder-causality /content/continued-cache/causality.json
```

Optional `--dataset-dir` accepts the staged repository directory on Drive, retaining its repository-relative shard paths. Every expected parquet shard is verified against SHA256 metadata at the hardcoded Hub revision before Arrow reads it. The loader does not fall back to unverified directories. `--base-model` can reuse a local `.nemo`, verified against the pinned Hub artifact metadata; otherwise the pinned artifact is resolved remotely. Network metadata access is required even for Drive files.

After final dev calibration, create a **test-specific** freeze without opening any dataset:

```sh
python benchmark_infer.py --split test --checkpoint /content/model/best.pt \
  --feature-manifest /content/cache/manifest.json --gate mean --batch-size 4 \
  --operating-point /content/final-operating-point.json \
  --freeze-out /content/freeze-test.json
```

The operating point JSON contains `threshold` and `recommit_s` (null or 1.5). Repeat the exact arguments, replace `--freeze-out` with `--freeze`, and add `--out /content/benchmark-test` to infer. Test access remains a parent-controlled final freeze decision; do not run this example during model selection. Test rejects `--dev-cache` and exports event times only. Original mean Silero history always feeds the head; `--gate last` changes only commit eligibility. One raw Silero pass derives both reductions.

The freeze pins all experiment/upstream Python sources, every recorded installed dependency file except generated bytecode, Python/package versions, head artifact, training-cache manifest, base encoder repo/revision/actual weight SHA256, continued evidence, Silero weights, operating point, gate, device/CUDA/cuDNN/TF32 settings, grid and batch size. Hashing installed package files incurs a sequential disk scan, potentially minutes on large environments. A changed dependency or newly added source file deliberately invalidates the freeze. Copy the complete final source tree before freezing. `--freeze-out` refuses overwrite. Freezes generated by the earlier limited format are incompatible.

Crash recovery: rerun the same inference arguments with `--resume`. The freeze is checked before dataset loading; dataset shard hashes and ordered IDs are checked before recovery. Each conversation is atomically committed after event validation. Partial temporary files are ignored. Partially completed batches are recomputed with their original membership, and already saved event predictions must match exactly. Fully completed batches are skipped; a fully complete run can rebuild the final official submission without loading inference models. Dev caches are written atomically before their conversation record and checked by hash on resume. Final coverage and event duration validation use the upstream submission API.
